2. Numbers kaise bante hain

HissaExampleMatlab
Branch codeGGNBranch ka code, jaise Gurgaon = GGN, Delhi = DEL. Har branch ki apni series.
DocumentINV / RCP / RFDINV = invoice, RCP = payment receipt, RFD = refund
Financial year26-27April 2026 se March 2027. Har 1 April ko counting 1 se dobara shuru.
Kram (sequence)00001Us branch, us document aur us saal ka agla number
  • Number database deta hai, bill ya payment save hote waqt. Koi staff khud number nahi daalta.
  • Beech mein number nahi chhootta. Agar payment beech mein fail ho jaaye, to uska number wapas ho jaata hai aur agla payment wahi number leta hai.
  • Prefix badalna: Settings › Billing › card "Invoice & receipt numbers". Har branch ke Invoice, Receipt aur Refund ka prefix alag likh sakte hain, jaise GGN/RCP ki jagah GUR-R. Wahi card agla number bhi dikhata hai.
  • Naya prefix agle bill se lagta hai. Jo number pehle chhap chuke hain, woh kabhi nahi badalte.
  • Do branches ek jaisa prefix nahi rakh sakti, warna ek jaisa number ban sakta tha. System aisa save hone hi nahi deta.
  • Purane invoices (jaise INV-00042) apne purane number ke saath hi rehte hain.

Refund slip par "Balance due" jaan-boojhkar nahi chhapta. System refund ke baad bill ka baaki amount badha deta hai. Agar slip par "Balance due ₹100" likha hota, to patient samajhta ki use abhi aur paise dene hain.

5. Payment lene ka poora flow

1Bill final hai (draft nahi). Take payment dabaiye: Invoice page, Invoices list, Outstanding ya Overview, kahin se bhi.
2Window mein patient, bill total, pehle diya gaya aur Outstanding dikhta hai. Method (Cash, UPI, Card...), amount aur reference (UPI txn id wagairah) bhariye.
3Record payment dabaiye. Payment save hoti hai aur database use receipt number deta hai, jaise GGN/RCP/26-27/00007.
4"Payment recorded" window khulti hai: kitna mila, mode, receipt no., kitna baaki. Yahan Print receipt dabaiye, ya Done.
5Agar clinic ne rule lagaya hai ("Payment received → Clinic payment receipt"), to receipt step 3 ke saath hi apne aap ban chuki hoti hai. Print receipt dabane par wahi copy khulti hai, nayi nahi banti.
6Receipt patient ke Files & Documents mein save ho jaati hai. Baad mein Invoice page ke Payments card mein Receipt button se dobara bhi chhap sakti hai.

Refund ka flow

1Invoice page › Payments card › payment ke saamne Refund dabaiye.
2Kitna wapas dena hai aur reason likhiye → Refund. Payment se zyada refund nahi ho sakta.
3Refund ki nayi row (↩ nishaan ke saath) aati hai aur use RFD number milta hai, jaise GGN/RFD/26-27/00001.
4Us row par Refund slip dabaiye, ya rule ho to slip apne aap ban chuki hoti hai.

6. Automatic documents kaise kaam karte hain

Settings › Automatic documents par clinic tay karta hai: "jab ye ho, to ye document apne aap bana do."

Screen kaise use karein

  1. Daayein "Applies to" mein chuniye: All branches ya koi ek branch.
  2. Baayein har module (Billing, Prescriptions, Pharmacy) ka card hai. Har row ek event hai, jaise "Payment received", aur usmein jo documents ban sakte hain unke checkbox hain.
  3. Tick lagaiye aur upar Save dabaiye. Save sirf usi scope (All branches ya woh branch) ke niyam badalta hai.
  4. Kisi branch ko chunne par "All branches" wale niyam ticked aur grey dikhte hain, saath mein All branches badge. Unhe wahan se nahi hata sakte; hatane ke liye "All branches" chuniye. Branch apne alag niyam jod sakti hai.
  5. Bina save kiye branch badlenge to system poochta hai: "Discard unsaved changes?"

Kis event par kya ban sakta hai

Event (jab ye ho)Ban sakta haiModule

Payment received, balance outstanding (kuch baaki hai)Clinic payment receipt, Clinic invoiceBilling

Screen par wahi events dikhte hain jinka module aapki organisation mein chalu hai. Galat jodi (jaise payment par prescription) na screen par milti hai, na server save karta hai.

Andar kya hota hai

1Staff payment save karta hai. Payment database mein pakka (commit) hone ke baad hi event uthta hai. Agar payment fail ya rollback hua, to koi event nahi aur koi receipt nahi.
2System dekhta hai ki is event ke liye kaunse niyam hain: "All branches" wale, aur jis branch par payment hui uske apne.
3Jaanch hoti hai ki us branch par Documents module (aur document ka module) chalu hai. Band hai to kuch nahi banta.
4Document branch ke published template se banta hai aur patient ke Files & Documents mein file hota hai.
5Kuch galat ho jaaye (template publish nahi, patient nahi) to payment phir bhi safe rehti hai. Receptionist ko "payment fail" nahi dikhta; galti sirf log mein jaati hai.
Abhi nahi hai: WhatsApp ya email se document patient ko bhejna. Documents sirf bante aur record mein file hote hain. Isliye screen par bhejne ka koi switch bhi nahi rakha gaya.

Kuch zaroori baatein

  • Duplicate rokne wali key patient_documents.idempotency_key hai, record par bani: clinic_receipt|App\Models\Tenant\InvoicePayment#42. Bill ke liye isme payment ya refund id bhi judti hai. Unique index hataye gaye documents par bhi lagta hai.
  • Queue nahi: document usi request mein, commit ke baad banta hai. Isliye queue:work ki zaroorat nahi.
  • Tenant safety: event us database ka naam saath rakhta hai jismein woh bana tha. Connection badal gaya ho to dispatcher use chalata hi nahi.
  • Niyam ki table mein "enabled" column nahi hai, row hona hi haan hai. location_id null ka matlab sabhi branches.
  • Nayi tenant migration aaye to hamesha php artisan tenants:migrate chalaiye. Ye naye document templates bhi seed karta hai.
